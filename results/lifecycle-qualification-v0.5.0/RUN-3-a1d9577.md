## Diagnosis summary (details: `DIAGNOSIS.md`)

Root causes **established** by structural counters and deterministic heap:

1. Emptied `BTreeSet` incidence sets retained a 104-byte leaf (`ett`, `hdt`). Fixed.
2. `hdt` upper levels retained isolated vertex records (history, not live state). Fixed.
3. Avoidable catalog work in bulk import (per-edge duplicate map, reallocation). Reduced.
4. Omitted reference work in the import comparison (effective-list derivation). Corrected prospectively.

Classified as **bounded, not defects** (D2, frozen 120-cycle rule: all 14
`same`/`toggle` cells PLATEAU, all 3 `fresh` cells BOUNDED_SAWTOOTH):

- `hdt` live level structure (spanning-forest copies of promoted tree edges):
  O(V log V); steady state reached (engine level 84.5 → 187 MiB, flat over
  cycles 80-120 at 100k). Present in the reference arm too.
- Vector capacity high-water (≤ 2× peak); `hashbrown` one-time doubling under
  delete/insert churn at > 50% load; retired engine slots (≤ 2V + 1024).

**Hypotheses tested and rejected** (frozen adoption rules): an alternative cut
order for high-degree removal (faster only on the star, 1-27% slower on every
generator); payload-order engine insertion for import (faster on `ett`/`hdt`
hub, 58% slower on `compact-bfs` hub).
