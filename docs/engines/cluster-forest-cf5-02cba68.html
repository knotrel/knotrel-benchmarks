ENGINE COMPARISON / ONE BUILD / NOT A RELEASE COMPARISON

cluster-forest compared with compact-bfs, ETT, HDT

Connectivity engines measured on the same Knotrel build (candidate 02cba68), on the same host and inputs. This page compares engines, not one release with another. Results hold only for the workloads, sizes, host and build measured.

Limitation. Host swap activity not verifiable; results accepted by the maintainer with this limitation. Swap occupancy was 738.25 MB at the start and at all 30 snapshots, and 722.25 MB at the end; the 192 zero values of the per-process swap counter concern only the V1 processes observed.

Decision. compact-bfs stays the default engine; cluster-forest is opt-in and experimental.

Method and perimeter

  • Campaign: v1.1.0 CF5, attempt 1, session 1 (2026-11-24 to 2026-11-25)
  • Candidate 02cba6825f9ad9ef769f4006428ccad5509076e9, tooling f4d41f19869c0a63baa0ce32d91ab02c1dd1522f
  • Host: Apple M3 (8 cores), 16 GB, macOS 26.5.2, Rust 1.100.0, AC power; server, PostgreSQL (S3 only) and load generator on the same machine
  • Paired design, 24 measured pairs per timed cell, interval [r(7), r(18)] of the paired log ratios (97.73 %); margins: time 10 %, tail 25 %, throughput 10 %, memory 20 %. K4 and L4 are deterministic allocator counts, one run per arm.
  • Host swap activity not verifiable; results accepted by the maintainer with this limitation. Swap occupancy was 738.25 MB at the start and at all 30 snapshots, and 722.25 MB at the end; the 192 zero values of the per-process swap counter concern only the V1 processes observed.
  • Statements hold only for the measured workloads, sizes and densities, this host, candidate 02cba68 and the server configurations used.
  • The measurement limit is a calibration estimate, not a mathematical bound; per-operation timing (K1, L3 churn) is not quantified.
