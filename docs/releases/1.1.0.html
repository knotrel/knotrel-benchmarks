Knotrel 1.1.0

Measured against v1.0.0 (d38df5f), the latest release at campaign freeze, built from source and measured again alongside the candidate. Regression checks of the existing engines only: V1 under the frozen v1.0.0 experiment A protocol, V2 under the CF5 rules. Knotrel 1.1.0 is a stable release. Performance qualification: accepted with exceptions (decision record ↗). Every verdict below is shown as measured; an exception does not change it. Binary identity with the measured build and a new measurement of 1.1.0 are not claimed. Host swap activity not verifiable; results accepted by the maintainer with this limitation.

Reading the tables

Each row has three separate fields: the verdict exactly as the campaign analyzer measured it, its category in the decision rule, and its execution status. No verdict is converted into another.

decisive
Enters the campaign decision rule; a non-PASS verdict needs a recorded maintainer disposition.
descriptive
Reported for context; it does not enter the decision rule.
disclosure
Reported by rule and never converted; it does not block the release.
completed
Measured and analyzed. Estimates are shown; a rule verdict, or a ratio with a zero reference, shows "Not available" and says why.
not run
Not measured (for example, after a product failure stopped its experiment). The reason is shown; there are no numbers.
nonconforming
Its block did not conform to the protocol (for example, a time cap). No verdict and no numbers.
failed
Ran without an analyzable result (a product failure or an invalid observation). The reason is shown; there are no numbers.

What this comparison covers

Response & capacity

Latency distributions, throughput, failures and concurrent updates.

Resource footprint

Steady/peak memory and CPU cost with explicit measurement boundaries.

Confidence & provenance

Independent runs, interval methods, exact revisions and linked evidence.

Missing coverage is not PASS. An accepted exception does not change a failed verdict.
